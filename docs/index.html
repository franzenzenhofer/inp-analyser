01 / The metric

What INP is.Three phases per tap.

Interaction to Next Paint is the Core Web Vital for responsiveness. For every page visit, the browser measures how long each click, tap and key press takes until the next frame is painted; the page's INP is (close to) the slowest of them. Google reports the 75th percentile over 28 days of real Chrome users.

0 200 ms 500 ms
good needs improvement poor

INP p75 thresholds from web.dev: good up to 200 ms, needs improvement up to 500 ms, poor above.

Every interaction has three phases, and each has different causes (Optimize INP):

  1. 01 Input delay

    The main thread is busy (often a long task) when the user taps.

    phase: input-delay
  2. 02 Processing duration

    The event handlers themselves run.

    phase: processing
  3. 03 Presentation delay

    Style, layout, paint and any script that squeezes in before the next frame.

    phase: presentation

Lighthouse and PSI give you a number. This tool gives you the reasons.

04 / How it works

Seven stages.One verdict.

One pinned, headless Chrome. One page load at a time, in seeded random order. Every stage feeds the next, and the end result is checked against the real-user number.

  1. Field data. CrUX and PSI per device, URL and origin level, plus 25 weeks of history, fetched before any page load.
  2. Discovery + safety guard. Two passes keep only stable targets. Money, deletion, logout and form-submit actions are never clicked; mutating requests and navigations are blocked.
  3. Screening. Every target is tapped once the page is idle, and while it is still booting, in 3 interleaved blocks.
  4. Deep-dive attribution. Every scenario slower than 200 ms gets timing blocks until the median CI is narrow, then 5 traced attribution runs.
  5. Third-party causal blocks. Paired runs with third parties allowed and blocked prove which owner costs how many milliseconds, or flag the result as confounded.
  6. Rules + statistics. 17 trace-based detectors, exact median CIs, Wilson intervals, Hodges-Lehmann shifts, Mann-Whitney with Holm correction.
  7. Report. Issues, comparisons and limitations, with a verdict on whether the lab reaches the field p75.

Every block is health-gated: if the machine drifts, the block is kept in the raw data but excluded from all statistics. The tool refuses to run on battery, in Low Power Mode or under thermal throttling.

05 / Quick start

Clone it.Run it on any URL.

Requirements: Node.js 26 or newer, git, and about 500 MB of disk for the pinned Chrome for Testing build. Runs on macOS and Linux.

git clone https://github.com/franzenzenhofer/inp-analyser
cd inp-analyser
npm ci
npm run chrome:install
export INP_GOOGLE_API_KEY=...   # optional: field data from CrUX + PSI
npx tsx src/cli.ts analyse https://en.wikipedia.org/wiki/Main_Page --quick

The key needs the Chrome UX Report API and the PageSpeed Insights API enabled. No key yet? Add --no-field for a lab-only run. --quick stops after screening (typically 20 to 40 minutes); drop it for the full analysis. Then open report.html in the run directory.

Commands

inp field <url>
CrUX + PSI field INP for phone and desktop. No page loads. Writes field.json.
inp discover <url>
Lists the interaction targets analyse would measure (two passes, stable targets only), their safety class, excluded targets with the reason, and global third-party listeners.
inp analyse <url>
The full pipeline: preflight, discovery, screening, deep-dive, third-party causal tests, diagnosis, report.
inp report <dir>
Rebuilds report.json and report.html from a run directory (runs.jsonl + meta.json).
inp trace <file>
Issues in an existing DevTools Performance recording (.json or .json.gz). One recording is one sample: no statistics.
inp compare <before> <after>
Before/after on two run directories: Hodges-Lehmann shift + 95% CI, Mann-Whitney p (Holm-corrected), Cliff's delta per shared scenario.
inp calibrate
Measures Lighthouse BenchmarkIndex under each CPU throttling rate on this machine and names the device class each rate reaches.

All commands, options and the full methodology: README on GitHub.

06 / Agent skill

Ask your agent.It knows the rules.

The repository ships an agent skill for Claude Code and other agents that read the skill format. It teaches the agent when to use the tool, how to read report.json, and to never present a lab number as the INP.

cp -R skills/inp-analyser ~/.claude/skills/

Then just ask:

  • "Why is INP poor on https://example.com/?"
  • "What INP does PSI show for https://en.wikipedia.org/wiki/Main_Page, phone and desktop?"
  • "Analyse this DevTools trace for slow interactions."
